1. Objetivo de la sesión

Al finalizar esta sesión, el aprendiz será capaz de instalar y configurar Django REST Framework (DRF) sobre un proyecto Django existente, explicar con sus propias palabras qué problema resuelve frente a las vistas tradicionales de Django, e identificar los componentes principales del framework (serializers, vistas, routers) que se trabajarán en las próximas sesiones.

2. ¿Qué es Django REST Framework y para qué sirve?

Hasta ahora construimos un proyecto Django ("Biblioteca") cuyas vistas devolvían texto plano con HttpResponse o páginas HTML con Templates. Eso funciona para un sitio web, pero no sirve si queremos que una app móvil, un frontend en React o cualquier otro sistema consuma nuestros datos sin depender de HTML.

Django REST Framework (DRF) es una librería que se instala sobre Django y añade todo lo necesario para exponer nuestros modelos como una API REST: convierte objetos Python/QuerySets a JSON (y viceversa), gestiona automáticamente los códigos de estado HTTP, ofrece autenticación y permisos listos para usar, y genera una interfaz de documentación navegable en el propio navegador.

💡 Idea clave
DRF no reemplaza a Django: se construye encima de Django. Los modelos, migraciones y el ORM que ya conoces siguen siendo exactamente los mismos. Lo único que cambia es la "capa de salida": en vez de un Template HTML, la vista devuelve JSON.

Los tres componentes que iremos dominando en las próximas sesiones son:

Componente¿Qué hace?
SerializerTraduce un objeto de modelo (o un QuerySet) a JSON, y valida/convierte JSON entrante de vuelta a datos de Python.
Vista (APIView / ViewSet)Recibe la petición HTTP, usa el serializer y el modelo, y decide qué respuesta y qué código de estado enviar.
RouterGenera automáticamente las URLs de un CRUD completo a partir de un ViewSet, sin escribirlas una por una.
3. Instalación y configuración de DRF

Vamos a instalar DRF sobre el mismo proyecto "Biblioteca" que construimos entre las sesiones 1 y 4.

Paso 1: Activar el entorno virtual del proyecto

# Windows
venv\Scripts\activate
# Mac/Linux
source venv/bin/activate

Paso 2: Instalar Django REST Framework

pip install djangorestframework

Paso 3: Registrar la app en el proyecto

Abre config/settings.py y agrega 'rest_framework' a INSTALLED_APPS, igual que registramos biblioteca en la sesión 1:

INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    'rest_framework',   # <-- Django REST Framework
    'biblioteca',
]
⚠ Error común
Olvidar este paso produce el error ModuleNotFoundError o que las vistas de DRF (como el navegador de la API) no aparezcan estilizadas. Recuerda: instalar con pip no es suficiente, siempre hay que registrar la app en INSTALLED_APPS.

Paso 4 (opcional pero recomendado): configuración global básica

En settings.py podemos definir comportamientos por defecto para toda la API, como la paginación (que veremos en detalle en la sesión 13):

REST_FRAMEWORK = {
    'DEFAULT_PAGINATION_CLASS': 'rest_framework.pagination.PageNumberPagination',
    'PAGE_SIZE': 10,
}
4. Ejemplo guiado: primer endpoint DRF

Vamos a crear el endpoint más simple posible: una vista basada en función, decorada con @api_view, que devuelve el listado de libros en formato JSON.

En biblioteca/views.py, agrega:

from rest_framework.decorators import api_view
from rest_framework.response import Response
from .models import Libro

@api_view(['GET'])
def listado_libros(request):
    libros = Libro.objects.all()
    datos = [
        {
            "id": libro.id,
            "titulo": libro.titulo,
            "autor": libro.autor.nombre,
            "precio": libro.precio,
            "disponible": libro.disponible,
        }
        for libro in libros
    ]
    return Response(datos)

Conecta la vista en biblioteca/urls.py:

from django.urls import path
from . import views

urlpatterns = [
    path('resumen/', views.resumen, name='resumen'),
    path('api/libros/', views.listado_libros, name='api_libros'),
]

Levanta el servidor con python manage.py runserver y visita http://127.0.0.1:8000/biblioteca/api/libros/. En vez de una página HTML común, DRF te muestra la Browsable API: una interfaz navegable con el JSON formateado, botones de método HTTP y opciones de filtro. Esta interfaz es una de las razones por las que DRF es tan usado: facilita muchísimo probar la API mientras se desarrolla.

5. Ejercicio práctico (para hacer en clase)
  1. Instala djangorestframework en el entorno virtual de tu proyecto personal y verifica la versión instalada con pip show djangorestframework.
  2. Registra 'rest_framework' en INSTALLED_APPS de tu proyecto.
  3. Crea una vista de función con @api_view(['GET']) que devuelva, en formato JSON, el listado completo de uno de tus modelos principales.
  4. Conecta esa vista a una ruta /api/<recurso>/ siguiendo el mismo procedimiento de urls.py + include() que ya conoces.
  5. Abre la ruta en el navegador y confirma que ves la Browsable API de DRF (no un error 500 ni un HttpResponse plano).
  6. Agrega al menos un campo calculado dentro del diccionario de respuesta (por ejemplo, un campo booleano o un texto derivado de otros atributos del modelo).
  7. Configura en settings.py la sección REST_FRAMEWORK con una paginación por defecto de 5 elementos por página.
6. Errores comunes
✗Instalar DRF con pip pero olvidar registrarlo en INSTALLED_APPS → la Browsable API no se estiliza o directamente falla.
✗Olvidar el decorador @api_view(['GET']) sobre la función → DRF no reconoce la vista como parte de la API y algunas utilidades (como los renderers) no funcionan.
✗Devolver directamente un QuerySet o un objeto de modelo dentro de Response() sin convertirlo antes a un tipo serializable (dict, list) → error de serialización. Este problema se resuelve de raíz con los Serializers que veremos en la sesión 6.
✗No activar el entorno virtual antes de instalar DRF → la librería queda instalada fuera del proyecto y ModuleNotFoundError aparece al importar rest_framework.
